# Tasks

Task service boundary. Wedding-wide tasks can omit eventId. Validate assignee/event wedding membership. FAMILY_MEMBER may update only assigned task status; creation, editing and deletion require OWNER/ADMIN. Keep reminderSentAt for future reminder deduplication.

Implemented increment (approved 2026-10-05): shared wedding checklist using the finalized Stitch desktop/mobile Overview, Empty, Add, Edit, Details, and Delete screens. The shared login can create, edit, delete, and update task status. The existing OWNER/ADMIN/FAMILY_MEMBER policies remain enforced server-side; a FAMILY_MEMBER may change only an already assigned task's status. Individual assignment/member management, My Tasks and reminders remain deferred. Activities integration was added in the 2026-10-08 increment below. This does not change the broader specifications or database schema.

Fields: title (required, at most 120 characters), one optional description (at most 5000), optional eventId and dueAt, LOW/MEDIUM/HIGH priority (default MEDIUM), and TODO/IN_PROGRESS/COMPLETED status (default TODO). The UI pairs optional date/time fields in IST. Past deadlines are permitted. Overdue is derived from an unfinished status and a deadline strictly before the response's asOf time; it is never persisted as a fourth status. Blank optional values clear their fields on edit; omitted fields are preserved.

Private APIs: GET/POST /api/v1/tasks, GET/PUT/DELETE /api/v1/tasks/{taskId}, and PATCH /api/v1/tasks/{taskId}/status. Mutations require the configured origin, bounded JSON, and a shared durable 60-per-minute limit per user. Status PATCH accepts only status. Scope/authorship come from the server-resolved session. Event linking uses a transaction and a write to the existing event's updatedAt to serialize against event deletion and prevent dangling references; no database fields or collections are added.

Lists are paginated (default 20, maximum 100), newest first with an ID tie-breaker. Supported filters: status, priority, eventId (including wedding-wide), overdue=true, literal case-insensitive title search, and API-only dueFrom/dueTo (ISO instants with explicit offsets, inclusive). Overall counts/progress are wedding-wide and independent of filters. Assignment mutations and assignedTo filters return a validation error until that increment is approved. Event options include the wedding's existing events, including past events. Suggestions prefill the Add form only; nothing is seeded.

The Activities increment (2026-10-08) now records transitions into Completed, including creation as completed, atomically with the task mutation. Identical completed saves produce no duplicate entry; event references coordinate with deletion. Dashboard completion refreshes recent activity. Other task-change generation remains deferred; see ../activities/README.md.

No task categories, separate notes, attachments, subtasks, comments, calendar sync, autosave, notifications, email, or reminder processing are enabled. Loading, no results, not found, input-preserving mutation errors, success feedback, and accessible delete confirmation are included. Follow /docs for future increments and unresolved decisions.
